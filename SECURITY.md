# Security Policy

## Supported versions

Security fixes are provided for the latest released version.

## Reporting a vulnerability

Do not open a public issue containing an exploit, real credential, private repository content, or other sensitive data. Use GitHub's **Security �� Report a vulnerability** flow for this repository. Include affected version, minimal reproduction steps, impact, and a suggested fix when available. Replace every real secret with a synthetic test value.

You should receive an acknowledgement within seven days. Maintainers will coordinate validation, remediation, release, and disclosure through the private report.

## Scope

Reports about plaintext exposure, unsafe path handling, command execution, malicious configuration behavior, SARIF/JSON leakage, or baseline leakage are in scope. Detection accuracy suggestions without a security impact may use a normal issue with synthetic examples.
